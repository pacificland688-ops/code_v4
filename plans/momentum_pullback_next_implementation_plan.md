## 先处理的三项实现边界

以下结论来自静态读码，新增反例由实施方提交、审核方独立复跑。

1. **预热起点可能制造有效重置。** `features.py:76`、`:77` 将首个 EMA 初始化为首收盘，`:99` 尚未按预热就绪限制 `price_known`；`event_engine.py:80` 直接将 `close<=EMA50` 作为有效重置。首值相等可能提前清除 `LEFT_CENSORED`。当前手工案例有长段平价，不能排除此问题。
2. **完整股票池不能由已读到的行情行自证。** `features.py:119`、`:122` 在传入的 day 上建立分母；`validate_normalized_panel` 只校验已经存在的证券。整只应有成分股缺失时，现有接口缺少外部完整名册对照；分股票批次直接调用也可能各自排名。已有测试覆盖了“证券在场但资格未知”，未覆盖整个证券消失。
3. **真实快照接入仍须开发。** `audit_local_prices` 固定返回 DATA_BLOCKED；当前 CLI 还有 REVIEWED_NORMALIZED_SNAPSHOT_REQUIRED 的拒绝分支。补字段、修改许可布尔值或删除拒绝分支，均不能代替来源认证、完整覆盖和快照验收。

这三项先闭合，再验收真实事件。已有价格/ADV20 时钟、未知资格传播、首次失败消耗编号等定义保留。

## 批次 A：规则补齐与数据来源裁定

**实施任务 A1：补齐状态及完整分母合同。**

- 建议增加 `feature_ready` 与 `reset_ready`。默认按共同前提的 150 个有效价格观测、完整必要价格历史及可评估 EMA 判断就绪；`price_known` 仅代表当前价格事实，不能单独证明重置有效。
- 上述就绪只涉及必要价格历史和 EMA；行业、市值、ADV20 未就绪不能成为价格周期重置的附加条件。根及候选另外检验当时成分/ST 与强势资格，匹配另外检验协变量。未知价格断层后的无效 EMA 不得作为重置证据。
- 在就绪前计算 EMA 供预热，但不以初始化值相等确认趋势重置。就绪后仍须实际观察有效 `close<=EMA50`；只有经验证历史检查点提供的状态可作为已知种子。具体就绪规则写入新草案，不能留给开发者自行选择。
- 由已审查的 PIT 成分事件表产生每天应有名册，再按当时 ST 与已知历史不足定义合法分母。未知历史不能当作零观测的已知不足。
- 股票批次仅计算各自价格特征；汇齐全部应有证券后进行一次横截面排名及匹配百分位计算。若保持一个函数，也必须以完整名册证据阻止对股票子集宣布分母完整。
- 候选池与身份跟踪集合分别说明：调出后仍需跟踪旧周期；重新调入不能自动将触碰编号归零。历史成员并集用于数据跟踪，不构成候选股票池扩展。
- 新草案记录就绪规则、名册内容身份及状态版本，维持 PROPOSED、无研究冻结、收益关闭。不得自动升级旧 r2 输出或检查点。

**实施任务 A2：裁定来源与可获得性。**

- 生成 `source_catalog.json`：字段语义、单位、覆盖区间、来源、修订/版本语义、发布时间证据、有效期及缺口。
- 生成 `factor_issue_ledger.parquet`：逐个异常证券/日期、原价/复价/因子可用性、事前范围分类、来源与拟处理方式。资格未知的记录不能归入“已证明池外”。
- 同时验证现有非缺失因子：明确因子是累积因子还是归一化调整系数，核对价格公式及尺度基准。不能为了符合当前校验器改写经济含义，也不以价格比推导未知因子。
- 从可信原始来源补录真实因子，衍生版本写入隔离目录，保留原缓存及差异。若价格尺度公式需要变更，先在草案写明并版本化。
- 成分用公告可用时点和生效区间；行业、ST、停牌、市值各自提供可用时点/有效期依据。时间一律带时区；有效期端点含义显式约定。
- 没有历史发布时间证据时保持 UNKNOWN。可证明的保守可用时间上界，须作为独立政策登记及审查；不能用文件下载时间、trade_date 或当前供应商更新时间补造历史事实。只有日期的公告需明确保守处理规则。
- 先裁定原范围的数据可行性；不能用失败后换年份、换板块或当前分类回填来解决。

**产物：** 新草案操作定义、来源目录、因子问题台账、PIT 成分/状态/行业事件与证据清单、`source_feasibility_report.md`。

**审核门 G-A：** 就绪规则与完整名册可唯一解释；每个必要字段有明确语义和证据状态；数据缺口可定位。无法取得的来源输出 SOURCE_UNAVAILABLE，暂缓依赖它的真实路径；规则修复和合成测试可继续。

## 批次 B：归一化快照与真正的数据门

**实施任务 B1：增加可审查的快照层。**

建议文件边界为 `source_bindings.py`、`snapshot.py`；等价拆分可接受，保持读取、校验、特征、事件、配对分层。

- 快照范围覆盖预热起点至输出终点，含每天完整应有名册及必要身份跟踪证券。新上市、历史不足、停牌、退市/调出和未知观测各有状态；不能靠只读到的证券或日期确定应有网格。
- 单位转换为明确的 CNY、股等标准字段；转换依据绑定来源。可用性、有效时间、观测日期和下载/修订日期分开保存。
- 原价/复价/因子关联须一对一，保留 lineage。重复、冲突、非法价、错误 OHLC、已知尺度不一致拒绝相关构建，不任意取最后一条。
- 全天停牌派生零成交额有独立来源记录，ADV20 仍是 20 个市场日；部分停牌、未验证停牌和未知成交额不填零。旧公共缓存保持只读。
- `snapshot_manifest.json` 绑定原始和归一化内容、完整名册、交易日历、源政策、合同、预热区间、模式 REAL/SYNTHETIC 及快照 ID。
- `source_review_receipt.json` 绑定审核范围、证据内容身份和未完成门；数据审核时间不是策略研究冻结时间。运行验证证据及绑定，不能只信任 VERIFIED 或 real_events_permitted 字段。

**实施任务 B2：替换静态拒绝为证据驱动的门。**

- 未认证必需来源、未知完整名册/日历、冲突连接或必要价格尺度失败：DATA_BLOCKED，仅输出审查和拒绝原因，禁止真实事件/配对。
- 已认证来源中的局部事实仍未知：PARTIALLY_EVALUABLE，按依赖传播到排名、周期和匹配。可输出明确标注的诊断及可确定部分，但不宣称整批验收通过，不进入 P3。
- 所有本阶段必要门通过：DATA_READY_FOR_ENGINEERING，允许新草案的真实特征、事件及固定配对；研究冻结和收益许可仍关闭。
- 已知历史不足、明确空候选池和正常零事件，与未知来源/身份/匹配失败分开。不得以“文件已写出”作为成功条件。
- 名册或日历整体缺失与个别列空值均须识别。关闭/损坏来源证据、修改内容或假改许可标志时，门必须重新失败。

**产物：** `snapshot_manifest.json`、`source_review_receipt.json`、`normalized_panel.parquet`、`universe_daily.parquet`、`calendar.parquet`、覆盖/缺口报告；暂不生成未来标签。

**审核门 G-B：** 抽查原始证据及必要连接，独立核对单位、时间与完整名册；恶意快照和虚假许可反例通过；数据文件与审核内容匹配。数据不齐则给出清楚的局部或全局阻断，禁止默默降级。

## 批次 C：固定 2018Q1 的真实事件与配对

**实施任务 C1：接入及续跑。**

- CLI 接入 `--input-manifest`，读取经审查的真实快照。来源认证、质量及合同门先于特征计算；真实与合成运行互不混用。
- 从统一起点预热，恢复检查点时验证合同、代码、源政策、名册、日历及已消费历史前缀。仅未来追加可续跑；历史修复或解释改变产生新运行并重放。
- 分股票批次、分月续跑和完整回放须得到相同的日截面分母、排名、状态、事件及配对。季度边界只筛选输出，继承就绪状态、EMA、滚动窗口、旧根和等待窗口。
- 数据门进入局部不可评估时保留因果路径：价格触碰可知而资格未知的编号继续消耗；可能漏根时身份持续未知；行业缺失按合同阻断匹配，不清空已知价格周期。

**实施任务 C2：固定名单及可逐项审核的输出。**

- 保存根、周期内额外突破、触碰段、候选、拒绝原因及普通强势对照资格；支持由 event_id 追到根、重置、源行和完整排名分母。
- 沿用同日同业、三只不同对照、原卡尺、同分规则、复用记录；名单先于任何未来标签固定。保留全部匹配失败，不放宽、不回头换人。
- 输出协变量平衡、数据/身份/匹配覆盖及状态数量。全日和证券行数与名册可核对；这些仅为工程覆盖指标，不能作为收益结论。
- 预先选取工程追踪样例：就绪前左截断、正常首触、失败后再触、连续段、20/21 日边界、缺失后未知、跨季度旧根和配对失败。选择标准基于边界/数据质量，不能依据未来表现。

**产物：** 真实运行清单、覆盖/缺口、特征、检查点、状态转移、根/突破/事件、固定配对、配对失败与平衡、`event_trace_examples.json`、工程摘要及全文件哈希清单。

**审核门 G-C：** 本助手独立复跑回归及新增反例，按边界抽查源行和事件链；同输入重复、分批与续跑结果一致；故意破坏门能真实阻断。审核结论为 PASS / CHANGES_REQUIRED / DATA_BLOCKED / PARTIAL，逐项列出依据，不凭事件数量或收益验收。

## 新增硬验收及手工预期

所有新测试须由输入与书面预期先定义，再实现；不能仅让两个实现互相比较。

- **WARM-01：** 从样本起点单调上涨，首 EMA 等于首收盘；就绪后无有效重置。即使出现突破/触碰，身份保持左截断，不得输出首次候选。
- **WARM-02：** 在 WARM-01 后加入就绪状态下的真实 close<=EMA50，再突破/首触，才能建立新根及编号 1。就绪前重置不充当就绪后的种子。
- **POOL-01：** 从已认证名册中删除整只应有成员的所有行情行，必须报缺失并阻断排名；不得把它标成已知历史不足。
- **POOL-02：** 完整名册不变，分成不同股票批次，只能汇总后产生一次相同排名和匹配百分位；不得各批取前 20%。
- **CAL-01：** 删除一个市场日的所有观测，或者同时删掉快照中的日历项；与已认证原日历对照必须发现，不得将短日历自证为完整。
- **SOURCE-01：** 只补列名/填 trade_date 为 available_at/把许可设 true，没有来源证据及正确绑定，仍阻断真实入口。
- **SOURCE-02：** 相同内容将公告时间移至截止点后、或生效日移至未来；不得提前使用。整段未知身份传播按合同验证。
- **FACTOR-01：** 缺因子、错误归一化基准、源价/复价键冲突均失败；可信来源的新因子版本重建后，一对一及尺度才可通过。原缓存内容不变。
- **STATE-09：** 调出后再调入且无有效重置，旧编号/未知状态继承；旧根、EMA 与窗口从 2017 延续到 2018。新增就绪字段也须经检查点继承。
- **REPRO-02：** 名册、日历、源时间政策或已消费历史改变，拒绝旧检查点与审核凭据；仅未来追加仍核验历史前缀并创建新运行。
- **EMPTY-02：** 数据真实完整且确实零触发，可报正常零事件；缺完整名册、左截断未解和全部配对不可评估分别报对应状态。
- **MATCH-03：** 追加/变更 t 之后的收益、成交和尾部数据，t 时点已锁名单不变；将失败对照剔除后补人应被测试拒绝。

既有 70 项测试继续回归；合约版本改变导致事件 ID/哈希改变时，比较解释后的语义及同一新版本内的确定性，不要求新旧版本字节相同。

## 实施方如何提交，审核方如何收口

建议拆成四个可审查提交：

1. **规则/边界修复：** 就绪与左截断、名册驱动分母、股票批次汇总；包含新草案和 WARM/POOL/CAL 的手工预期及测试。
2. **来源及缺口证据包：** 来源目录、因子台账、时间/尺度政策与可行性裁定；不要求用伪数据凑齐 READY。
3. **快照及数据门：** 归一化、lineage、审核内容绑定、真假来源反例、真实 CLI 接入口。依赖前两项；不能直接删除静态拒绝来“解锁”。
4. **真实 P2 工程包：** 固定季度预热/续跑、事件追踪、配对和覆盖；依赖经审核的快照和门。

每次提交提供改动文件/差异、合同和代码版本、输入清单、准确复跑命令、测试报告、手工预期、运行清单、产物哈希、仍未通过的门。环境复用已验隔离解释器；依赖改变需单独重验导入和 Parquet，而非全局升级。

本助手收到提交后：先静态审查时点/状态/分母与源绑定，再独立复跑必要测试及有界工程结果，最后输出明确审核结论和具体待改项。需要修复的业务代码及新增业务测试由实施方处理；审核方不代为开发。
